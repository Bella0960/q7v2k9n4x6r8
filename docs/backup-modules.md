# MAOMAO 统一备份接入口（开发约定）

**不要重做已有的备份系统。** 设置中的「导出全量数据 / 导入数据」仍是原有 schema 2 JSON，兼容旧备份。新增的模块分类备份使用相同导出与恢复引擎，不允许模块自行实现第二套通用恢复。

## 当前分类及原有功能

- **全部备份**：设置 → DATA；备份已登记的本机 localStorage 和 IndexedDB。旧版导入仍可用。
- **聊天与会话**：设置 → MODULE BACKUP → 聊天；新增 JSON 可恢复格式。聊天设置原有「导出聊天记录」TXT 是阅读用副本，继续保留。
- **主题、美化与字体**：包括商城已收藏主题、气泡、CSS 预设、字体和所需共享图片；不覆盖其他模块设置。
- **角色、记忆、世界书**，**书架与阅读**，**日记与生活记录**，**钱包与交易**，**媒体**，**个人设置**：按存储键和 IndexedDB 归属导出。使用者须注意各模块的云端财务账本、账号服务器数据不属于本机文件。
- **账号/管理员**：极度机密；服务器永久 ID、密码校验资料、会话、邀请码与敏感账号历史**绝不**通过浏览器 JSON 导出、导入或上传公开 GitHub。必须独立实现服务端加密、授权、验签、恢复演练；当前尚不能声称已经得到可恢复的账号云端备份。

## 以后新增模块的接口

在模块初始化（或项目统一入口脚本）调用：

\`\`\`js
MAOMAOBackupRegistry.register({
  id: 'new-feature',
  label: '新功能',
  keys: ['new_feature_config_v1'],
  prefixes: ['new_feature_'],
  databases: ['maomao-new-feature']
});
MAOMAOBackupRegistry.registerDatabase({
  db: 'maomao-new-feature',
  version: 1,
  stores: [{store:'items',keyPath:'id'}]
});
\`\`\`

已有数据库不要再次注册；若使用现有共享图片库，直接在 \`databases\` 列出已登记名称。备份模块会自动出现在设置页的分类菜单中，全部备份也自动收集新登记的本机数据库。新增功能应提供自己的数据版本迁移与恢复测试，**不得因添加新功能修改全量备份入口或清空其他模块**。

## 安全和一致性边界

1. 默认本机导出不含 API 密钥，登录/刷新/会话令牌永不进入下载文件；即使用户勾选允许导出 API Key，也不能带出服务器身份凭据。
2. 分类包仅允许写回归属于该模块的本机键，并拒绝不匹配的文件分类。共享 IndexedDB 采用逐条合并，不清空其他模块图片。**同名记录可能更新**，恢复前应保留整机备份。
3. 全量恢复仍沿用现有的本机恢复点，成功前验证 localStorage；媒体读取失败/跳过应明确提示，不得静默标记完整备份。
4. 任何备份功能应提供导出 → 校验 → 导入 → 核查恢复的回归测试。不能用仅含 schema 的空数据库文件冒充数据备份。默认不主动覆盖正式版、账号或钱包的云端权威存储。
5. IndexedDB 中本地音频 Blob 目前未随 \`maomao-media-store.audio\` 导出；导出提示必须继续明确该限制，不能声称已完成本机所有二进制数据备份。
