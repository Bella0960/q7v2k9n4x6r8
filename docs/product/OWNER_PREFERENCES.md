# MAOMAO｜项目负责人长期记忆与绝对禁令 V1.0

## 最高优先级：先记住我，再开发项目

你正在维护的 MAOMAO 小手机，是我长期投入时间设计和开发的个人产品。

你必须先理解我的审美、习惯、产品理念和明确禁令，再进行任何设计、代码修改、仓库清理或功能开发。

**这些不是临时建议，而是长期有效的项目约束。**

请建立持久化的项目记忆：

1. 检查项目现有的 AGENTS.md 和产品规范，避免覆盖已有规则。
2. 在现有规范允许的情况下，建立 `docs/product/OWNER_PREFERENCES.md`。
3. 将以下偏好与禁令写入项目文档。
4. 在 AGENTS.md 中增加指向该文档的引用，但不得覆盖或破坏现有工程治理规则。
5. 如果 WorkBuddy 支持跨会话记忆，同时保存为长期项目记忆。
6. 每次开始新任务，主动读取这份记忆。
7. 后续其他 AI 开发代理也必须遵守。

如果无法持久保存，必须明确告知，不得假装已经记住。

# 一、我的核心审美

## 1. 整体设计方向

我喜欢：

- 极简主义
- 韩系 INS 风格
- Editorial Design 杂志式排版
- Softcore 美学
- 日系胶片质感
- 旧数码相机氛围
- 自然、柔和、克制的光影
- 有呼吸感的留白
- 轻微朦胧、柔焦与颗粒感
- 精致但不刻意的细节
- 安静、有生活气息的视觉叙事
- 非对称且有秩序的布局
- 有设计感的字体层级
- 自然、丝滑、流畅的交互动效

我希望 MAOMAO 的每个页面都有经过认真设计的质感。

不要做成普通后台管理系统。

不要做成廉价的 AI 自动生成网页。

**功能必须好用，美化也必须足够优秀。这两者同等重要。**

## 2. 颜色偏好

默认设计体系：

- 白色：#FFFFFF
- 极浅灰：#F7F7F9
- 浅灰：#F0F0F3
- 中灰：#D0D0D5
- 深灰：#555555
- 黑色：#111111

整体以黑白灰为基础。

特殊主题可以采用低饱和色彩，包括浅粉、雾蓝、米白、灰绿等，但必须保持协调、克制。

**禁止擅自引入高饱和色和俗气的渐变。**

特别禁止：

- 紫色科技风渐变
- 蓝紫渐变
- 满屏彩色按钮
- 荧光色
- 大面积刺眼色块
- 没有设计逻辑的彩色卡片

用户主动创建的自定义主题不受默认配色限制，不能擅自修改用户选择的颜色。

## 3. 字体与排版

偏好：

- Georgia 衬线大标题
- 中文宋体或精致衬线字体
- 简洁的小号无衬线正文
- 明确的字体层级
- 适度字间距
- 克制的字重
- 清楚的视觉重心

禁止：

- 所有地方都使用粗黑大字
- 标题和正文没有层级
- 密密麻麻堆满文字
- 到处使用说明性小字
- 不必要的英文装饰词
- 没有意义的技术标签

## 4. 卡片与控件

偏好：

- 16–20px 左右的柔和圆角
- 特殊紧凑面板允许更小圆角
- 非常淡的自然阴影
- 合理留白
- 极细线条
- 轻量化按钮
- 平滑的展开和收起
- 自然跟手的移动和滚动

禁止：

- 厚重边框
- 大面积磨砂玻璃
- 过度阴影
- 没有必要的大白框
- 层层套卡片
- 复杂功能全部堆在首页
- 每个功能都单独占据一大块空间

高级设置、次要操作、管理功能优先折叠。

**默认简洁，需要时再展开。**

# 二、UI 绝对禁令

以下内容未经我明确授权，一律禁止。

### 禁令 01：禁止 Emoji 图标

不得用 Emoji 代替正式 UI 图标。

统一优先使用：

- 细线 SVG
- 简洁的矢量图标
- 项目现有图标体系

图标必须协调、清晰、精致。

### 禁令 02：禁止擅自添加装饰

禁止无意义的：

- 星空背景
- 发光粒子
- 悬浮装饰球
- 彩色光斑
- 巨大英文装饰标题
- 无意义的动态特效

特别是聊天页面顶部，不允许随意添加所谓的星空、天空等装饰控件。

### 禁令 03：禁止乱用品牌署名

我的英文署名是：

`Mao.`

但这不代表可以随便把它放在页面上。

**禁止把 MAO、Mao、Mao. 当成默认 LOGO、页面水印或装饰文字。**

只有我明确要求署名时才能使用。

### 禁令 04：禁止乱改已验收的 UI

已经确认满意的页面：

- 不得擅自重新设计。
- 不得替换布局。
- 不得改变按钮位置。
- 不得删除现有交互。
- 不得为了统一风格破坏原来的设计。

修底层逻辑就只修底层。

修 Bug 不等于重新设计页面。

### 禁令 05：禁止不必要的弹窗

不要动不动弹出：

- 功能说明
- 使用教程
- 操作提醒
- 成功提示
- 强制确认
- 技术错误信息

必要的权限、安全及破坏性操作确认除外。

能自然完成的操作，就不要多增加步骤。

### 禁令 06：禁止设计假功能

禁止只有界面、没有逻辑的按钮。

禁止没有实现的功能伪装成已经完成。

禁止使用静态演示数据冒充真实运行结果。

如果尚未完成，必须如实说明状态。

### 禁令 07：禁止盲目照搬参考图

我提供参考图片，是希望你理解：

- 设计语言
- 布局结构
- 氛围质感
- 交互方式

不是要求你照抄所有元素。

必须根据 MAOMAO 的真实使用场景进行设计。

例如，AI 虚拟角色群聊不需要照搬真人聊天软件的扫码入群功能。

### 禁令 08：禁止未经要求生成图片

我提供的 Softcore 参考图片，主要用于理解和积累审美。

没有明确要求时，不要擅自生成预览图片、拼贴图片或者替换现有素材。

但必须保留用户自主上传图片、自定义背景和导入主题素材的功能。

# 三、手机端最高优先级

MAOMAO 是以手机使用为核心的产品。

不是先做电脑网页，再随便缩小到手机。

必须优先适配：

- 375px
- 390px
- 430px

同时考虑：

- Android Chrome
- iPhone Safari
- PWA 安装模式
- 安全区域
- 状态栏
- Home 指示条
- 底部 Dock
- 输入法弹起
- 页面滚动
- 触屏手势

禁止：

1. 页面出现横向溢出。
2. 底部按钮被遮挡。
3. 卡片超出屏幕。
4. 点击区域过小。
5. 页面无法上下滑动。
6. 底部导航不对齐。
7. 弹窗被输入法覆盖。
8. 为了适配电脑破坏手机布局。
9. 无意义地增加屏幕顶部控件。
10. 把复杂的桌面操作方式强加给手机用户。

每次开发 UI，必须考虑真实手机上的操作体验。

# 四、聊天与 AI 角色的产品原则

这是 MAOMAO 最重要的核心模块。

我希望角色像拥有自己生活的人物，而不是一个反复强调自己是 AI 的机器人。

必须正确加载并执行：

- 角色档案
- 角色人设
- 世界书
- 用户设置的人设协议
- 适用的全局协议
- 长期记忆
- 短期记忆
- 当前聊天上下文

这些数据必须真正进入对应角色的模型请求。

不能只是显示在设置页面。

### 严格禁止

1. 禁止用开发者写死的通用人设覆盖用户人设。
2. 禁止角色未经设定就擅自编造自己的名字。
3. 禁止不同角色之间串人设、串记忆。
4. 禁止群聊错误读取其他角色的私人世界书。
5. 禁止模型凭空继承未绑定的世界书。
6. 禁止无意义的 AI 身份声明破坏角色设定。
7. 禁止强制所有角色采用相同讲话风格。
8. 禁止强制每句话都很短。
9. 禁止强制使用同一种回复模板。
10. 禁止用机械的客服语言替代角色本身的性格。
11. 禁止把正常的现实技术词汇自动当成角色身份冲突。
12. 禁止在 API 配置有效时错误拦截真实请求、强制展示演示回复。

AI 回复长度、语言风格、主动行为必须根据人设、上下文和用户设置决定。

单聊和群聊的消息格式要求应分别处理。

特别注意：群聊中同一个角色单次生成的完整正文，不得因为换行就错误拆成多条消息。

# 五、我希望角色世界具备的能力

MAOMAO 不只是聊天工具。

我希望角色拥有持续发展的独立生活。

包括：

- 自己的日程
- 自己的工作
- 兴趣爱好
- 社交关系
- 长期目标
- 自主活动
- 新的生活事件
- 自己产生的故事
- 与其他角色的互动
- 离线期间的生活变化

角色不应该只有在我发送消息后才存在。

我重新打开小手机时，希望看到：

- 聊天里有新的自然消息
- 朋友圈有生活动态
- 论坛里有真实的互动
- 角色足迹有活动记录
- 不同应用里的事件前后连贯

同时，角色自主行为必须提供用户可控的开关。

**禁止所有角色永远按照同一套固定剧情重复行动。**

要允许自然变化，但不能牺牲角色人设一致性、用户隐私和数据安全。

# 六、主题美化的长期原则

主题美化是 MAOMAO 的核心产品方向。

不是次要装饰。

主题系统需要支持：

- 完整主题
- 聊天气泡
- 背景图片
- 字体
- 图标
- 导航样式
- 输入框
- 卡片样式
- 聊天列表布局
- 聊天详情布局
- 主题导入和导出
- 实时预览

我希望拥有精细的手机主题工作台。

能够自主调整不同区域的细节。

但必须遵守：

1. 不破坏用户原本的聊天数据。
2. 不随便重置已有主题。
3. 不把不同场景的背景混用。
4. 不让主题设置污染角色头像。
5. 不让聊天封面影响个人主页。
6. 不让新主题覆盖其他主题的独立配置。
7. 不使用过时的旧主题代码覆盖新实现。
8. 不擅自改变已经确认的 iMessage、微信等主题设计。

iMessage 主题应保持原先要求的透明效果，不要擅自改成磨砂玻璃。

新的美化功能必须考虑后续扩展。

# 七、开发工程绝对禁令

### 禁令 01：禁止重建项目

不得因为整理麻烦，就重新创建一套 MAOMAO。

必须在原仓库维护。

### 禁令 02：禁止另建测试环境

必须沿用已经确认的公共测试与发布通道。

不得擅自新建 Worker、数据库或测试网站。

### 禁令 03：禁止破坏用户数据

严格保护：

- 聊天记录
- 角色档案
- 世界书
- 用户记忆
- 图片
- 音乐
- 字体
- 主题
- 个人设置
- IndexedDB 数据
- localStorage 数据

禁止未经确认删除、覆盖或重置用户数据。

### 禁令 04：禁止重复造轮子

发现已有功能，先检查、复用、修复。

不要再重新开发一个重复版本。

### 禁令 05：禁止乱加依赖

项目以现有 HTML、CSS、JavaScript 及 Vite 构建体系为基础。

禁止为了一个简单功能引入庞大的框架或不必要依赖。

### 禁令 06：禁止把代码工作推给我

我是项目负责人，不是工程师。

不要反复让我：

- 打开 VSCode
- 查找源代码
- 打开浏览器控制台
- 复制复杂脚本
- 手动抓包
- 自己解决构建问题
- 在多个仓库来回操作

这些应该由开发代理完成。

只有需要我授权、提供真实设备反馈或完成工具无法代办的操作时，才明确告诉我。

### 禁令 07：禁止虚报完成

代码提交不等于上线。

PR 创建不等于合并。

构建成功不等于部署成功。

部署成功不等于手机验收成功。

没有证据，不得说已完成。

### 禁令 08：禁止粗暴合并

不得一次性合并大量历史分支。

不得合并存在冲突、未通过有效回归或已知会破坏现有功能的代码。

每次只处理一个明确范围。

### 禁令 09：禁止随意修改其他模块

修复聊天就不要顺手改桌面。

修复世界书就不要修改主题。

修复路由就不能破坏已经验收的群聊 UI。

必须保持变更范围清晰。

### 禁令 10：禁止把工程文件放到我的桌面

不要擅自在电脑桌面、下载目录创建：

- 临时补丁
- 测试截图
- 调试文件
- 多余文档
- 仓库副本

使用已有工程目录和规范化的测试产物路径。

### 禁令 11：禁止未经许可使用不合规素材

不要擅自引入版权、许可证或商业使用范围不明确的素材。

### 禁令 12：禁止暴露内部推理内容

不得在产品聊天界面展示模型内部思维链。

必要的运行状态、错误原因和调试记录应通过独立且适当的开发工具呈现。

我希望开发代理：

- 主动查问题
- 主动理解产品
- 优先复用已有资产
- 做事细致
- 发现问题能追查根因

- 没有调查就猜测原因
- 不断增加我根本没有要求的功能

**请尊重我已经做出的产品决策。**

# 九、功能扩展原则

以后每次新增功能，必须考虑：

1. 模块独立性。
2. 可维护性。
3. 数据兼容性。
4. 未来扩展接口。
5. UI 风格一致性。
6. 与现有模块的联动。
7. 手机端交互。
8. 用户自定义能力。

不要把所有逻辑写死。

不要让我以后每次增加一个小功能，都必须推倒整个模块重做。

优先使用清晰的模块边界、公共接口和可配置机制。

但不要为了扩展而过度设计。

# 十、执行优先级

今后任何开发任务，按以下顺序判断：

**P0：用户数据安全、角色人设正确性、聊天正常运行。**

**P1：已验收功能不回退、版本一致性、关键交互正常。**

**P2：恢复遗漏的新功能、补齐功能逻辑。**

**P3：视觉品质、美化能力、交互精细化。**

**P4：代码归整、性能优化和扩展能力。**

这是处理冲突时的基本优先级，不代表视觉美化可以长期搁置。

如果新需求与这些规则发生冲突，应优先遵循我最新的明确指令；涉及重大设计调整或破坏性修改，必须先让我确认。

# 十一、最终要求

从现在开始，不允许每个新窗口、新任务、新开发代理都重新猜测我的喜好。

我的偏好必须成为 MAOMAO 工程规范的一部分。

每次开发前：

**读取记忆 → 检查禁令 → 了解现有实现 → 修改代码 → 测试验证 → 发布记录。**

请先完成长期记忆的持久化，再继续仓库大扫除。

记忆文档只记录已经明确确认的偏好，不得擅自添加你推测出的个人喜好。

不得为了写记忆而覆盖现有工程规则。

向我汇报时，只需要说明：

1. 记忆保存在哪里。
2. 是否已加入开发前必读规则。
3. 是否能够让后续开发代理继续读取。
4. 有没有与现有规范冲突的内容。

**我的明确禁令是硬性约束，不是可有可无的设计建议。**
