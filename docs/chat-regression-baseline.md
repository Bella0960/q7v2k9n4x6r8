## 1. 如何使用

运行命令：**npm run test:chat:contract**

该命令运行 Node.js 内置测试，不新增运行时依赖。测试包含四类检查：共享消息策略的可见性/搜索资格断言、内部推理标签清洗、记忆标记提取的行为断言，以及关键源码契约检查。它不是浏览器端到端测试，也不能证明 UI、API 或存储在真实设备上正常运行。

- 测试代码：tests/chat-regression-contract.test.mjs
- 合成数据：tests/fixtures/chat-message-cases.json
- 完整的职责及兼容约束：docs/chat-architecture-contract.md

项目当前的 npm run lint 只是打印固定文字，不能当成真正的 lint 或测试结果。

## 3. 合成消息样例覆盖

tests/fixtures/chat-message-cases.json 覆盖普通用户消息、旧版 content 字段、图片、贴纸、赴约模式消息、silent 指令、system_error、群成员身份、转发消息和无文本通话卡。

样例使用虚构文本与占位图片数据，不含用户真实聊天记录。新增行为测试会把样例交给 `ChatMessagePolicy`，断言线上显示与搜索资格；`includedInContext` 目前仍是规划用预期字段，尚未由该模块测试，因为上下文组装仍留在详情页。

## 4. 最小人工验收顺序

继续拆分其他逻辑前，建议实际运行并记录以下顺序；如某一步原本就失败，应先记录为既有问题，不要误判成重构回归。

1. 选择一个私聊角色，发送一条普通消息，等待完整流式回复。
2. 发送图片或贴纸，确认图片/贴纸显示正常，模型能按现有语义理解。
3. 重生成最近一条 AI 回复，检查历史和消息索引。
4. 打开群聊测试成员身份与自动接话；确认单聊历史不受影响。
5. 从聊天进入赴约模式，发送一条剧情消息，返回后确认线上/线下各自显示规则正常。
6. 在记忆空间检查现有记忆，再触发一次记忆相关流程，确认角色数据未串。
7. 从通话、钱包或论坛中执行一个确实会写聊天历史的动作，检查记录写入目标。
8. 刷新页面并返回列表，再次打开相同会话，确认消息仍在。
9. 在手机 PWA 上重复至少第 1、3、5、8 步。

测试记录至少写明：设备/浏览器、角色或群聊类型、执行日期、通过/失败、复现步骤和控制台错误。不要将 API 真实密钥或真实聊天内容写入日志、测试夹具或截图。

## 5. 哪些自动检查已经提供

tests/chat-regression-contract.test.mjs 包含共享消息策略的行为测试，并检查以下静态契约：

- 聊天详情的 load/save 入口和 PhoneStorage 角色作用域；
- 线上详情与搜索对 mode=date、silent、历史异常文本和错误消息的过滤约定；
- mid、role/text/content、群成员身份与模型上下文映射；
- PhoneStream 调用、部分回复结果、超时机制；
- 上下文字符预算和旧聊天检索的上限参数；
- 记忆标记、权重记忆和 MemoryRecall 的关键入口；
- chat-extras 当前使用的页面全局桥接符号；
- 赴约剧情共享聊天历史的既有存储 key；
- PhoneStorage 的旧 key 兼容及成功写入后再整理重复副本的行为；
- 已知跨页面聊天历史调用方在迁移清单中仍然存在。

行为测试只覆盖已抽离的纯消息判断；其余大多数检查仍是结构性断言。它们能拦截一部分不慎删除接口或兼容分支的改动，但不能检测每一条业务路径的运行异常，也不验证 CSS、点击交互、真实网络请求和 localStorage 配额。
