# 小手机（phone-simulator）创意思路 · 设计规范 · 下一步功能规划

> 本文档回答两件事：
> 1. 这个项目到底在做什么、为什么长现在这个样子（创意思路 / 设计语言）。
> 2. 按现有清单，下一步还能加什么新功能、该先补什么洞。

---

## 一、创意思路：这不是一个网站，是"一部住在浏览器里的手机"

### 1.1 一句话定位

用纯原生 HTML/CSS/JS 模拟一部 390×844 的智能手机。桌面上不是导航菜单，而是宫格 App 图标；点开每个 App，它背后都围着同一个东西转——**你自己捏的那个 AI 角色**。

也就是说，这不是"AI 聊天工具 + 一堆玩具"，而是：

> **给 AI 角色一个家。** 角色住在这部手机里：他会发朋友圈（空间）、会接电话、会在咖啡馆打工、会开直播、会写小说、会和你一起旅行、会留下足迹。你打开手机，是在"看他的生活"，而不是"和他对话"。

### 1.2 三层设计动机

| 层 | 想解决什么 | 具体做法 |
|---|---|---|
| 壳 | 让人一眼认出"这是手机"而不是网页 | 手机边框、状态栏实时时钟、Dock、宫格、挂件、底部四 tab 导航、左滑右滑翻页 |
| 生态 | 让角色"活着"，而不只是对话框 | 一个角色 = 一套数据：朋友圈、记账、足迹、游戏战绩、咖啡馆存档、记忆、世界书全部按 contactId 隔离 |
| 情感 | 模拟"等一个人回消息"的牵挂感 | 流式打字机、未读红点、赴约线下剧情、倒计时挂件、陪伴日历、直播间打赏 |

### 1.3 核心世界观（为什么所有 App 长一个样）

整部手机只有一个"主演"。所以所有 App 共享同一套世界观设定（世界书）、同一套长期记忆、同一套玩家身份（面具 mask）。
你在聊天里对他说的话，会沉淀进记忆；记忆会反过来影响他发什么朋友圈、在咖啡馆点什么单、小说里写什么剧情。
这就是 `PhoneContext`（组装 system prompt：人设 + 世界书 + 长期记忆 + 近期聊天 + 其他 App 数据）的意义——**每个 App 都是这个角色人生的一个切面**。

## 二、设计语言：黑白灰 × 极简 × 杂志海报

项目默认视觉不是 iOS 风、不是 Material、不是微信绿，而是一套**"私人杂志 / 艺术海报"**的编辑排版语言。三个词拆开看。

### 2.1 黑白灰（Monochrome Paper）

整站几乎不出现彩色。颜色只出现在两类地方：AI 角色的头像、背景图（封面图、商品图、旅行图）。

为什么这么做：
- 彩色社交软件（微信/微博/小红书）会吵闹，会让"角色"淹没在 UI 里。
- 黑白灰把界面压成一张**纸**，角色的照片、头像变成纸上唯一的颜料，反而更突出、更像珍藏的剪报。
- 也和"日记、小说工坊、视觉档案、阅读"这些安静的内容气质一致。

**固定色板（Design Tokens）**，全站各页 `:root` 基本统一：

| 变量 | 色值 | 用途 |
|---|---|---|
| `--paper` | `#f7f7f5` | 页面底色（微微发黄的纸，不是纯白） |
| `--white` | `#ffffff` | 卡片 / 输入框底 |
| `--ink` | `#171717` | 主文字、分割线、反白按钮 |
| `--muted` | `#777777` | 次要文字、kicker 标签 |
| `--line` | `#d8d8d4` | 细分割线、边框 |
| 图片 | — | 一律 `filter: grayscale(1)` 压成黑白照片 |

### 2.2 极简（Minimal）

- **没有阴影、没有渐变、没有花哨图标**。分隔靠 1px 细线（`border-bottom: 1px solid`），不靠阴影分层。
- **圆角极小**：按钮 `border-radius: 2~3px`，只有胶囊按钮和手机壳用大圆角。和 iOS 的大圆角刻意区分开。
- **大量留白**，信息密度低，一页只讲一件事。
- 交互反馈克制：悬浮只做 `translateY(-3px)` 轻微上浮，active 按钮直接反白（黑底白字）。

### 2.3 杂志海报排版（Editorial Poster）

这是最有辨识度的一层，规律如下：

1. **大标题用衬线体**：`Georgia, "Times New Roman", "Songti SC", serif`，而不是手机系统黑体。
   - 字号极大且流式：`clamp(54px, 12vw, 112px)`
   - 字距压紧：`letter-spacing: -.075em`（大标题紧排才有杂志感）
   - 行距压扁：`line-height: .82`
2. **斜体副题**：大标题下用 `font-style: italic` 的小字做注释，像杂志的引言。
3. **kicker 眉题**：页面顶部一行 10px、全大写、字距 `.18~.22em` 的小标签（如 `VISUAL ARCHIVE`、`NO. 001`），先给分类，再上标题。
4. **编号化**：每条内容一个斜体编号 `item-no`（`NO.01`、`NO.02`），像画廊展品。
5. **不对称 12 栏网格**：海报网格里卡片错落 `span 7 / span 5 / span 4`，不是整齐的一行几个，而是杂志拼版。
6. **正文用无衬线**：Arial / PingFang / 微软雅黑，12~13px，行高 1.7~1.8，和大衬线标题形成"衬线标题 + 黑体正文"的经典搭配。

> 一句话总结这套气质：**像翻开一本安静的独立杂志，而不是打开一个 App。**

### 2.4 分区原则（重要）

不是所有地方都走杂志风，项目里有一条明确的分界线：

- **"微信聊天"板块（chat-detail / 气泡 / 朋友圈）**：必须高度还原微信原生样式，气泡、头像、时间戳、绿色回复尽量贴真机。这部分是"和他对话"的沉浸区，不能用杂志排版破坏真实感。
- **其他板块（世界书、视觉档案、小说工坊、设置、桌面）**：自由发挥，走黑白灰杂志风，不需要模仿微信。
- **换肤层**：`beauty/`（聊天美化中心）+ `liquid-glass-theme.css`（液态玻璃主题）允许用户在这套基底上改气泡颜色、加毛玻璃，但底层排版骨架不变。

## 三、下一步还能做什么（新功能建议）

下面按"补一个真实手机该有的 App"和"让角色更活"两类列。每个都标注了和现有架构怎么接。

### 3.1 补缺：一部真手机该有、现在还没有的 App

| 优先级 | 新 App | 为什么值得做 | 怎么接现有架构 |
|---|---|---|---|
| 高 | **相册** | 现在图片散在贴纸、朋友圈、足迹、拍立得挂件里，没有一个统一"回忆"入口。做一个黑白灰画廊（杂志网格正好用上），汇总角色头像、聊天图、足迹照、旅行票根 | 新建 `album/`，数据从 `chat_history_<id>` 的 image 消息 + `moments` + 足迹里抽，只读聚合 |
| 高 | **相机 / 拍立得** | 现在桌面有 polaroid 挂件但不能"拍照"。加一个相机 App：选角色 + 场景 + 滤镜，AI 生成一张黑白拍立得，自动进相册、自动发朋友圈 | 走 `PhoneAPI`（非流式 JSON 任务），返回图片描述后用占位画框或生成图；存档进 `phoneData[contactId].album` |
| 中 | **天气** | 桌面挂件里没有天气。天气还能联动角色心情：下雨 = 角色发emo朋友圈；晴天 = 约你出门（接现有 date 线下模式） | 新 `weather/`，数据可本地随机生成 + 按角色 mood 加权，不需要真接天气 API |
| 中 | **闹钟 / 时钟** | 现在只有 clock 挂件显示时间。加"叫他起床"闹钟：到点角色主动发一条消息（模拟推送），是很强的情感钩子 | 纯前端做不到真推送，做成"打开 App 时检查到点未读"的模拟推送，写进 `chat_history_<id>` |
| 中 | **备忘录** | 桌面有 note 挂件但没有独立 App。做成角色的手账便签，AI 自动写"今天想了什么" | 注册进 `PHONE_APPS`，prompt 让 AI 根据最近聊天生成 3 条便签 |
| 低 | **浏览器 / 搜索** | 模拟打开一个极简浏览器，首页是黑白灰 Google 风，点进去其实是角色"搜自己/搜你"的剧情 | 纯前端假页面，链接跳论坛或角色朋友圈 |
| 低 | **邮件** | 角色给你写长信，比聊天更私密，配合小说工坊的 serif 排版 | 复用 date.html 的流式续写，落点 `phoneData[contactId].mail` |

### 3.2 加深：让现有 App 之间更"串通"

现在 App 之间已经通过 `phone_data_v2` 按角色隔离，但还可以做几个高收益联动：

1. **"他今天干嘛了"日报**：打开手机锁屏/首屏，用一段 AI 总结角色今天的动态（朋友圈 + 咖啡馆营业 + 记账 + 聊天摘要），像翻开日记本扉页。
2. **相册和朋友圈打通**：拍立得 App 拍完，一键"发空间"，自动带灰滤镜和斜体编号。
3. **天气 → 旅行/赴约**：下雨就不建议出门，旅行票根自动变成"雨天室内咖啡馆"剧情。
4. **游戏大厅连胜 → 他发朋友圈炫耀**：`maomao_game_stats_v1` 变化时触发一条动态。

### 3.3 必须先补的洞（技术债，不然后面加新功能会踩雷）

这些是 CLAUDE.md 里自己标记、但还没处理的，按危险程度排：

1. **【最大隐患】聊天记录无上限**：`chat_history_<id>` 存全部消息（含 base64 图片/贴纸），localStorage 总共只有 ~5MB。聊久了会写不进去、丢数据。建议：历史消息只留最近 N 条在内存，旧的归档压缩或定期导出。
2. **PWA 被禁用**：`sw.js` 注册代码被注释，手机浏览器现在"添加到主屏幕"用不了，装不成真正的 App。建议解决缓存问题后重新启用 SW。
3. **孤儿目录 `apps/settings/`**：没人引用的旧样式副本，可直接删。
4. **旧散装 localStorage 没收敛**：很多老页面还在裸调 `localStorage.getItem`，没走 `PhoneStorage`，备份/迁移时会漏。
5. **残留数据 `bubble_presets`**：写入了但没有任何页面读，可清理。

## 四、给下一轮开发的一句话清单

> **先做"相册 + 相机拍立得"**：它最贴黑白灰杂志风（画廊网格现成的），情感收益最高（和角色合影），还能顺便把图片数据收拢，缓解 5MB 配额压力。
> 风格上继续守一条线：**聊天区像微信，其他区像独立杂志；全站只有灰，角色才是颜色。**
