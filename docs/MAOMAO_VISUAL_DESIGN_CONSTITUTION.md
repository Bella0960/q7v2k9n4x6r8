
# MAOMAO 视觉设计准则

> 本文件是 MAOMAO 所有页面、独立样机、UI 改造和视觉提案的长期约束。开始设计前必须先读；不可只记住“极简”两个字，然后套普通 App 模板。

## 0. 规则优先级

1. 用户对当前页面最新、明确的要求。
2. 用户亲自提供或明确认可的参考图，以及本文件对这些图的归纳。
3. 本文件中的长期视觉规范。
4. 通用 UI 经验和设计模型默认值。

不得以“常见 App 做法”“现在流行的风格”覆盖用户明确偏好。某个主题或某张参考图的局部颜色，不代表全站都要使用那种颜色。

## 1. 总体视觉方向

**黑白灰、编辑式极简、独立设计刊物感。**

关键词：安静、精致、轻盈、准确、阅读感、留白、字体比例、微妙错落、克制的层次。画面应通过字体、内容结构、间距、对齐和少量细节建立质感，不靠大量卡片、装饰、渐变和阴影堆出“高级感”。

默认适用：
- 白色或极浅中性灰背景。
- 近黑色标题、深灰正文、中灰辅助文字、浅灰细线。
- 中文信息清晰优先；衬线字体可用于有张力的标题，正文使用可读的无衬线字体。
- 有目的的留白和轻微非对称，不要为了显得高级而拉成长页面。
- 以手机 375–430px 视口为首要设计对象。

常用中性色参考：#FFFFFF、#F7F7F9、#F0F0F3、#171717、#333333、#555555、#888888、#999999、#D0D0D5、#E5E5E5。

默认不要擅自加入紫、蓝、粉、高饱和色、彩色渐变、霓虹、玻璃彩光或发光边缘。用户明确要求某个页面有颜色时，颜色应局限在该页面或用户选定的内容中，不能扩散成全站新主题。日记编辑页可比日记列表更丰富，但不能默认做成一套浅紫/粉蓝的模板。

## 2. 排版与构图

- 大标题可以用优雅衬线字体，中文标题也可以有字重和字形张力。
- 不要为了“设计感”硬塞英文眉题、期号、编号、品牌名或大段装饰文案。
- 英文只有确有信息意义时才出现。
- 标题、正文、元信息的层级要明确；不要所有文字都同一尺寸，也不要每一行都做标签。
- 可使用有控制的错位、文字叠层、留白和图片拼贴，但必须保持阅读顺序清楚。
- 细线只在有结构意义时使用。连续横线会让页面碎裂；能用间距和排版区分的地方，不要再加线。

## 3. 卡片、列表与密度

- 不要默认使用多列圆角卡片墙，也不要把每条内容都做成厚重独立卡片。
- 卡片只用于确实需要聚合的信息；尺寸紧凑，圆角、边框和阴影都要克制。
- 不要超大卡片、超大内边距、过宽空白、长条堆叠或整屏都是卡片。
- 首屏先展示核心内容和少量近期信息；低频设置用低调入口、抽屉或局部面板按需展开。
- 不为追求“干净”删除已有功能、信息或可发现性；需要收纳时用合理分组和按需展开。
- 不要把一页改成大量筛选栏、统计数字、提示语、导语和装饰信息的集合。

## 4. 图标、品牌与禁止元素

以下为硬性禁止，除非用户在当前任务中明确要求：

- 不擅自加入用户姓名、英文名、昵称、项目名、品牌名、Logo、工作室名、签名或水印。仅当明确要求时才可使用对应标识；个人签名资产使用 Mao.，但不能自动加在普通页面。
- 不使用上箭头图标或上箭头字符作装饰，也不在标题、按钮、页脚或提示旁堆装饰箭头。
- 不用 Emoji、颜文字、动物图案或无意义小图标装饰页面。
- 不增加无意义英文小字、VOL/ISSUE 编号、虚构栏目名、虚构品牌文案、冗余标签。
- 不擅自使用紫/蓝/粉色渐变、霓虹光、重投影、玻璃彩光、厚重边框和高光装饰。
- 不以密集横线切碎布局；不堆砌大卡片、方块和装饰性控件。
- 不以“更现代”“更活泼”为由覆盖用户原先确认过的视觉体系。

## 5. 已有参考图的正确解读

这些图应学习其排版、信息关系、留白、材质与动效，不复制图上的品牌、人物、文字、Logo 或水印。

### A. Forum 编辑式首页

参考特征：白底、超大衬线标题、清晰中文正文、少量英文元信息、主题分类、内容区和底部导航；细线数量少，留白有节奏。它适合普通信息首页、目录和内容列表。

### B. 黑白 Message / 社交动态界面

参考特征：黑白摄影拼贴、图片与文字叠层、内容条目清楚、头像和元信息克制、少量细线分组。学习编辑式拼贴与信息布局，不要复制参考内容或把所有页面做成拼贴海报。

### C. Living Typography /「雨声档案」文字实验

参考特征：深色工作区、大型衬线字、前后层次、微小元信息、空间感和动态文字效果。适合专门的创作/编辑器、视觉实验、沉浸式页面或某个明确要求的主题；**不是普通列表页的默认模板**。动效要由交互触发或有明确含义，不要全屏持续晃动。

### D. 信件与纸张排版

参考特征：温暖纸白、克制的边缘、衬线标题、正文舒适行距、留白充分、像真实纸面一样的阅读节奏。适合信件、日记阅读和写作页面，不代表普通列表必须变成复古信纸。

### E. 用户手绘的日记列表草图

结构要点：多条紧凑、纵向排列的记录；每条卡片或条目内容一目了然；日期与心情在同一行，心情靠近日期行的末端；正文直接展示；照片作为右侧小缩略图；写日记入口轻量、容易找到。不要再把列表做成几张占据大半屏幕的超大卡片。

## 6. 日记模块专属规则

### 列表首页
- 打开日记就直接看到记录，不先铺大幅 Today 封面、巨型统计区、每日提示或多层装饰横线。
- 标题区紧凑；搜索入口易找但不占大面积。
- 每条记录以紧凑的横向信息单元呈现。日期与心情同一行，心情紧跟在日期之后或靠近该行尾部。
- 正文摘要是主信息，标题可选；不要用大标题占掉正文空间。
- 有照片时放小型右侧缩略图；无照片时文字自然占满宽度。
- 记录之间主要靠适当间距和极浅层次区分，不要每个元素都画线。
- 首屏应能连续浏览多条记录；禁止大卡片导致一屏只能看到一条。
- 新建入口使用轻量笔形或加号按钮；点击后直接进入写作，不先经过繁琐菜单。
- 心情标签默认保持低调中性；不擅自给每种心情套一套鲜艳颜色。

### 写作与阅读
- 写作页可以比列表页更有表现力，有更丰富的排版、纸张质感、配图和可选颜色，但默认仍需精致、可读、可控，不能直接套用浅紫/粉蓝大卡片模板。
- 写作界面中的颜色应由有意义的选择或内容决定，最好允许用户选择；不要强制把所有日记变成同一种彩色主题。
- 阅读页重视正文、行距和图片；不要塞入与阅读无关的统计、筛选和广告式装饰。
- 任何视觉调整必须保留已有日记字段、存储键、照片数据库、搜索、日历、收藏、备份导入导出、角色批注等现有功能，除非用户明确要求改变。

## 7. 动效和交互

- 动效轻、短、明确，常规转场约 0.18–0.28 秒；淡入、轻微位移和状态变化优先。
- 不用大幅弹跳、持续晃动、闪烁或无意义循环。
- 用户重视动态交互，但动效应服务于特定操作，不是为了让页面“看起来很动”。
- 真实手机触摸、桌面鼠标和键盘焦点都要考虑；视觉样式不能替代真实交互。

## 8. 预览和交付

- 优先提供真实手机视口的单屏预览。不同交互状态分开截图，不拼接成超长图。
- 明确区分真实页面截图、静态示意图和可交互原型。
- 正式页面之外做样机时，放在独立 preview 路径，不覆盖生产页面。
- 先给用户看首页首屏，再看写作/弹层等独立状态；没有确认之前，不将样机的设计强行应用到正式页面。

## 9. 每次动手前后检查

设计前：
1. 先读本文件和当前页面真实代码。
2. 找出与当前功能有关的用户参考图，而不是只看通用模板。
3. 明确哪些图是普通页面参考、哪些只适合创作编辑器或特殊主题。
4. 先画清楚信息层级和首屏密度，再写 CSS。

提交前：
1. 是否保持黑白灰编辑式极简（或符合用户明确要求的局部例外）？
2. 是否出现不必要横线、大卡片、卡片墙、彩色渐变或大块留白？
3. 日期、心情、正文、照片是否一眼可读？
4. 是否擅自添加品牌、名字、英文装饰、Emoji、箭头或无意义图标？
5. 手机首屏密度是否合理？是否能一次看到多条记录？
6. 原有功能、数据字段、存储、页面入口和交互是否保留？
7. 预览是否独立、单屏、清楚标注，并先于正式替换交给用户确认？
