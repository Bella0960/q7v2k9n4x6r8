# 邂逅 / Encounter — MAOMAO 原生角色抽卡应用

Task ID: FEATURE-ENCOUNTER-001
状态：首阶段功能已提交独立分支，待构建及移动端验收。

## 1. 目标

一个真正可游玩的原生多页面应用：免费浏览人物短卡，喜欢后候选收藏，再进入现有角色档案创建；不重写聊天、账号、世界书和记忆。不将番外模板/时间档案馆混入本次范围。不部署正式版。

## 2. 视觉与首页

低饱和冷灰与白 (#f6f6f5、#fff、#cbccca、#343633)，黑白灰 Editorial Design，轻薄衬线姓名、密度克制、清晰留白、无高饱和色/Emoji/紫色渐变/额外 Logo。默认头像是原创的缺口甜甜圈形抽象圆环，正式创建后沿用原有角色头像编辑。

首页只有返回、标题「邂逅」、右上角「···」、一张主卡、两侧露出的叠卡、PASS/收藏、候选收藏入口。偏好选项隐藏在底部抽屉，勿堆叠工具按钮。

交互：横向拖动超过 9px 且大于纵向位移时跟手旋转；移动 95px 后右划收藏、左划 PASS；不足阈值回弹；转场 240–260ms。点击/键盘可打开人物短档案，尊重 prefers-reduced-motion。375–430px 手机优先兼容桌面外壳。

## 3. 数据闭环

1. 免费本地抽卡：组合种族、时代、职业、性格、反差、物件与命运线索，完全不调用 API。
2. 姓名查重：读取正式角色/别名、候选收藏、当次抽卡已出现姓名；NFKC 标准化、移除多余空格/间隔点后比对，旧人设优先，绝不自动改名。
3. PASS 只跳卡，不写正式角色、聊天、记忆或推送。
4. 收藏需先确认本地持久化成功，失败时保留当前卡片并提示；候选上限 80 位。
5. 候选可移除、查看、去创建；仅在明确点击后转到既有角色编辑器，并回填短人设。
6. 用户确认保存后才通过原有 PhoneStorage / ai_custom_characters 写正式角色；成功后尝试清理对应候选，失败须提示。头像在原角色库自由更换。
7. 正式 AI 完善（首阶段已编码，尚未真实 API 验收）：候选人物可以先免费保存为正式角色，之后仍可回到原角色编辑器选择「AI 完善人设 · 使用 API」。只有用户手动点击并确认后，才会通过现有 PhoneAPI.complete 请求一次；发起请求之前会预检草稿存储与候选状态。生成结果先放入可编辑草稿，用户再次确认保存后才更新角色。存储失败必须明确提示复制内容，不能声称成功，也不自动重试付费请求。

存储键：maomao_encounter_candidates_v1（轻量小数据，版本 1，不含二进制/密钥/对话）；maomao_encounter_preferences_v1（本地偏好）。正式角色 ID 仍由原系统产生，人物关系必须基于 ID 而非姓名。 新创建的邂逅角色另外保留 encounterOrigin 版本化元数据（种族/时代/职业/物件/命运线索/卡片来源 ID），以供后续剧情扩展；其他旧角色无需迁移。当前没有自动跨设备同步，不得依赖尚未验收的云同步。

## 4. 玩法与扩展

第一阶段：普通相遇、蒙面档案、以物识人、命运分支、性格盲测；保留共享抽卡卡池与持久化模型，并开放 MAOMAOEncounter.registerCardDecorator(fn) 与 subscribe(fn) 扩展接口。

角色种族：人类、精灵、血族、狐族、龙族、人鱼、狼族、神族、仿生人等；默认排除哥布林。时代：现代、古代、东方幻想、西方奇幻、未来、现代异闻、神话。人类角色为成年人；长生种允许数百乃至上千年经历。世界与职业在合理集合内组合，避免逻辑冲突。

人物相似度由用户决定，不强制去重；偏好包含完全随机、多来喜欢的类型、探索不同类型。后续可增加稀有角色（非付费）、缘分再遇、永久屏蔽、双人关联卡、彼此认识的家人/同事/宿敌、关系分支、穿越重生/时间循环的内在设定。现有角色关系写入须经用户确认，禁止随机修改已存人物历史。时空档案馆暂缓，与番外系统保持独立。

## 5. 角色 JSON 边界

编辑器导出 MAOMAO 自有格式：JSON 对象 format=maomao-character，version=1，character 包含 name、persona、tone、appearanceDescription、styleKeywords。只导出人物文字，不导出私聊、记忆、头像、API Key。

JSON 导入只接受该格式与字段，不直接兼容酒馆、SillyTavern 等第三方人物卡，不提供格式转换。原有 TXT 普通文本导入保留。格式检查不等于加密签名或来源认证，按用户要求不做繁琐来源验证。

## 7. 严格数据回归 — 2026-11-15

- 真实缺陷：原角色管理的 loadRoles() 在角色 JSON 读取异常时会调用 saveRoles([])，存在把损坏但仍可恢复的角色记录覆盖为空数组的风险。现改为读取失败绝不写入，roleStoreReadError 禁止全部角色写入，同时角色列表显示「资料读取失败」的警示。正常空库依然允许首次创建。
- 修正 PhoneStorage.result.getCharacters() 实际错误形状为 error.code（非顶层 code），抽卡引擎在读取异常时阻断新卡生成，不得把异常当作空库。
- 手势：仅拦截一次滑动结束后合成的 click，不再用固定 480ms 同时拦截用户下一次正常点击；键盘与弹层焦点逻辑仍保留。
- 人设生成费用：请求前预存草稿；候选已删除或角色已切走时不得继续生成/覆盖；响应非空但较短时保留草稿，存储失败则明确提示复制，不假称已保存。
- 已正式创建的邂逅角色仍可随时回原角色档案选择 AI 完善；不会因为没有及时生成完整人设而必须重新抽卡。
- 已审查 chat/chat/chat.html 的聊天列表数据来源为 ai_custom_characters，正式角色沿用现有聊天入口与 role.id；未另建聊天数据表。
