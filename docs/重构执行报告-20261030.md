### ✅ 2. 修复 phone_stream HTTP 错误被吞（报告 P1 真 Bug）

**文件**：`shared/js/phone/phone_stream.js`

`finish()` 加 `settled` 幂等锁。原因：HTTP 错误分支先 `finish({kind:'http'})`，链尾 `.then(function(){ finish(null) })` 无条件再跑一次，`result` 是同一个闭包对象，resolve 之后仍被改写为 `ok:true, error:null`。

修复前 401/429 在调用方表现为"成功但无内容"，用户永远看不到"API Key 无效"。

### ✅ 3. 修复 chat-detail 的 XSS 注入链（报告 P0）

**文件**：`chat/chat/chat-detail.html`、`chat/chat/chat.html`

新增三个工具（与既有 `escHtml` 放在一起）：

| 工具 | 作用 |
|---|---|
| `safeUrl(u)` | URL 协议白名单：`data:image/*` / `http(s):` / `blob:` / 相对路径，其余返回空串 |
| `safeCssUrl(u)` | `background-image` 专用，先过白名单再转义引号与括号 |
| `fillAvatar(el, src, fallback)` | 头像统一入口，用 `createElement + .src` 赋值而非拼 `innerHTML` |

逐点修复：

| 位置 | 修复前 | 修复后 |
|---|---|---|
| 图片消息 | `src="' + String(msg.img) + '"` | `safeUrl` + `escHtml`，不通过则降级占位框 |
| 心声卡 | `' + heartText + '`（**来自 AI 输出**） | `escHtml` |
| 语音转文字 | `' + String(msg.text) + '` | `escHtml` |
| 位置 / 纪念日 / 待办 / 时刻卡 | `${loc.label}`、`${a.name}`、`${i.text}`、`${m.title}` 等 | 全部 `escHtml` |
| 通话卡 | `${cardTitle}`、`${c.text}` | `escHtml` |
| 名片卡 | `String(cd.avatar)`、`String(cd.name)` | `safeUrl` + `escHtml` |
| 礼物卡 | `style.backgroundImage = 'url(' + g.img + ')'`（CSS 注入） | `safeCssUrl`；祝福语 `escHtml` |
| 头像（4 处） | `` `<img src="${...}">` `` | `fillAvatar` |
| 转发面板 | `t.avatar` / `t.name` 只转了引号 | `safeUrl` + `escHtml` |
| 贴纸 | `String(msg.img \|\| '')` | `safeUrl` |

`chat/chat/chat.html` 的聊天列表同源问题一并修掉（新增 `safeImgSrc`）：群头像 `g.avatar`、成员头像 `m.avatar`、角色头像 `role.avatar`。

### ✅ 5. 消息渲染性能优化（报告 P1 / P2）

**文件**：`chat/chat/chat-detail.html`

- `appendMessageToDOM(msg, idx, container)` 新增可选容器参数。传 `DocumentFragment` 即可离屏组装。
- `renderAllMessages()` 改为：先装进 DocumentFragment，再一次 `appendChild`。**原来 N 条消息 = N 次 live-DOM append = N 次潜在重排**，这是"每收到一条回复就卡一下"的主要来源。
- 另外三处批量重建（重新生成、删除单条、批量删除）同样改为 Fragment。
- 修了一个隐蔽分支：思维链/旁白无正文时会走 `chatMessages.appendChild(el)` 提前 return，绕过了容器——一并改为宿主容器，否则 Fragment 模式下这批节点会漏掉。
- 语音播放定时器提到外层 `voicePlayTimer`，`renderAllMessages()` 开头统一 `stopVoicePlay()`。原来重渲染后定时器仍持有已脱离文档的节点跑到结束。
