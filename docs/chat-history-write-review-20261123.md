**性质：** 只读复核 + 结论记录。本文件不改动任何业务代码、存储键、消息结构或用户数据。
**取代：** `docs/chat-history-callers.md` 第 4 节中关于下列调用点的风险描述（该节保留 2026-11-11 审计基线）。

## 1. 复核方法

逐个调用点只读源码，确认三件事：是否整段读取历史再写回、写入失败是否会被察觉、成功提示是否以「写后读回」为条件。并对照 #370 / #371 / #372 / #305 / #358 / #361 / #366 的改动范围，判断哪些问题已被认领。

## 4. 结论

`couple.html`、`forum-detail.html`、`chat-notifier.js`、`date/journey.html` 这四个重点文件中，**没有发现未被上述 PR 覆盖的「静默丢数据」缺陷**：失败已被察觉，成功提示已与持久化结果绑定。因此本轮不提交行为补丁，避免与并行分支做同一处改动。

真实剩余风险是共享的 CAS 原语：只要 `PhoneStorage.saveChatHistory` 仍是「读整段 → 改 → 覆盖写」，任何调用点都存在并发丢更新窗口。正确做法是在 #366 / #361 落地 CAS 后，由 DATA-008 按调用点逐一收口，而不是在每个页面各写一份补丁。
