# MAOMAO 查手机｜虚构角色剧情

状态：独立功能分支；未合并 main、未部署、未真机验收。

## 入口与边界

桌面 → 查手机 → 选择角色 → 原手机锁屏 → 角色许可 → 勾选板块 → 查看剧情。

此功能不访问真实设备通讯录、GPS、相册、支付、搜索历史。聊天、钱包、相册、地图全部是虚构角色记录；不会写入现有角色聊天记录或真实钱包数据库。

存储键使用 inspect_story_v1_ 加 URI 编码角色 ID，并包含当地日期、共享事件时间线、各板块内容与许可状态。账号授权分支的标准 localStorage 隔离机制可直接作用于此模块。

## 已实现

- 微信：六位虚构联系人，包括具名好友和群聊；每组 8–12 条对话，撤回、未读、已读未回，发送时以角色身份发言。
- 朋友圈：至少 3 条；有配图文字、可见范围、评论和犹豫标记。
- 浏览器：搜索、两条夜间记录、删除痕迹、实用书签。
- 备忘录：公开和锁定记录、创建修改时间、剧情 PIN 默认 111111。
- 钱包：收入、5–8 笔支出、余额、当月支出与最大支出类别。
- 音乐：近期播放、循环、歌单、常听前三。
- 地图：四个停留点、独白、步数、移动距离；仅为文本故事，不请求定位权限。
- 相册：文字描述、隐藏区、照片统计与单独 PIN。
- 设备状态：虚构设备信息、常用应用、屏幕与深夜使用情况。
- 论坛：保留为可选剧情扩展（不读取真实论坛帖子）。

所有板块有统一的 facts 事件时间线。未配置聊天 API 时明确标记「本地剧情样例」；点板块刷新才请求已配置的 API。生成结果数量不足、结构错误或出现未来时间时，旧数据不被覆盖。

角色允许查看普通内容，不等于授权查看锁定内容。秘密随角色关系推进而分层露出；密码仅用于游戏剧情，并非实际加密保护。尝试打开锁定内容、停留和切换板块会影响虚构的被发现风险。

## 验收

运行 npm run test:inspect:contract；完整构建运行 npm run build；在启动本地预览后运行 node tests/inspect-phone-gesture.test.mjs。

手机验收重点：390px 窄屏、首次上滑、角色隔离、反复切换、返回、单板块刷新、错误保留、聊天对话与 PIN。

**已验证**：JS 语法解析，模拟 DOM 下从解锁许可 → 选择板块 → 进入备忘录 → 密码表单的交互；本地虚构数据的数量、角色隔离键及三个板块的事件映射。

**未验证**：Node 全套测试、实际 Vite build、Playwright Chromium 和真实手机运行。GitHub Actions 曾有额度/runner 无法运行的问题，不能将没有执行的 CI 当作通过。

待后续加强：从角色日历导入真正的事实主表、语义冲突自动审查、跨日增量生活事件、与账号分支集成后的实机权限验证。
