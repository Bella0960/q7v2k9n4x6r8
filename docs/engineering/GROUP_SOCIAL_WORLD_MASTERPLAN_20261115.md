# MAOMAO｜群聊社交世界升级总纲（2026-11-15）

> 状态：正式需求设计基线；实现分阶段提交到 Draft PR #298。**本文件不是已完成验收清单。** 主入口、已有角色库、群历史、钱包/账号和原群玩法不得因扩建被替换。

## 1. 产品目标

让每个群聊具有独立氛围、共同经历、关系网、日常节奏与游戏历史。群内成员拥有不同角色人设，能够自主聊天、互相 @、私聊、开玩笑、发起投票和活动，但不会机械刷屏、全天候在线或为了剧情强行制造冲突。

**设计原则**：黑白灰细排版；聊天主页面只有必需操作，次要操作放右上角「···」；群聊设置只显示五个清晰入口，进入某个类别才显示其内容，高级选项默认折叠。新增功能通过注册接口扩展而非在聊天页面继续粘贴分支。

## 3. 群聊设置 IA（信息架构）

`群聊 ··· → 群聊对话设置` 打开群聊专属设置，而不是复制单聊设置。

1. **群聊氛围**：线上/线下、自然接话、作息、自动追问、群内普通私聊、旁观模式；简单的「安静 / 自然 / 热闹」作为将来默认模式，底层频率由统一 AI 调度控制。
2. **成员与关系**：成员名片、专属头衔、权限标识、关系、参与倾向、活跃作息。默认只显示头像/昵称/身份，展开才编辑。
3. **群聊记忆**：连接已有记忆空间的群聊版，查看真实事件与手动固定记忆；自动总结、跨群召回、事件证据校验后续分期落地。
4. **游戏与活动**：进入本群已有投票、接龙和游戏；本局规则在开始游戏前设置；未实现游戏不能显示可操作却无效的开关。
5. **群主管理**：角色自主管理、任免管理员、转让群主、私有的游戏规则、主持人指定、邀请开关等。**仅属于群主的策略/数据不应出现在角色可用的提示词及 API 响应**，未来云端真人群必须在服务端授权后才返回。

退出群聊是用户的个人操作，不属于只能由群主看到的功能。保留聊天历史。

### 游戏开关约定

- 「允许玩家私聊」默认按游戏模板指定，开始后冻结；关闭时应同时阻止通过普通角色私聊/云端任务绕过本局规则。
- 「显示私聊动向」只在允许私聊时可调整；显示参与者和时间，不泄露内容；默认关闭。
- 「主持人」可选用户/有资格的角色；主持人可以发**私密身份牌**，不等于其他成员能阅读秘密。
- 管理员不能改这三项群主锁定的规则。参与者只得到游戏的公开状态、自己身份、合法可见信息。
- 停止/重开一局创建新 `gameSessionId`；不得把上一局秘密带给下一局。主持人身份如果需公开，只公开名字，不公开群主策略。

## 4. 可扩展架构

### 4.1 现有唯一事实源
- `phone_groups`：群基本资料、成员、身份/头衔、群级设置（历史兼容）。
- `chat_history_<groupId>` / `PhoneStorage`：群消息，原始历史保留。
- `ai_custom_characters`：角色人设唯一事实源。群成员引用 ID，不修改原人物名和性格。
- `MemoryRecall` 的 `chat_memories_<groupId>`：本群确认过的长期记忆，独立于单角色 ID。
- `GroupGovernance`：`registerAction`/`apply`/`on`，当前群管理动作唯一推荐路径。
- 钱包统一共享账本：唯一余额与收款凭据源；群红包仅持有交易/结算 ID 和消息显示状态。

### 4.2 统一事件及扩展点（协议草案，未宣称实现）

`GroupFeatureRegistry.register({id, version, capabilities, onEvent, onRender, migrations})`；每个功能只注册自身，不直接修改其他模块局部状态。建议事件：`group:message`、`group:member-joined`、`group:member-left`、`group:title-changed`、`group:game-started`、`group:game-ended`、`group:memory-confirmed`、`group:wallet-settled`。

事件统一携带 `eventId`（幂等去重）、`groupId`、`actorId`、`occurredAt`、`visibility`、`sourceRef`、`version`；写入成功后再投递，订阅者失败不得伪造成功。权限在执行层再次校验，不能仅隐藏按钮或信任 AI 的机器标签。账号真人群需另加同源服务器授权和账号隔离，客户端身份不是认证。

### 4.3 群聊记忆契约

每条事件/记忆需要 `groupId`、`participants[]`、`summary`、`sourceMessageId`（或游戏/钱包凭据）、`visibility`（public | participant | host | private）、`status`（pending | confirmed | corrected）、时间和重要度；用户可手动修改/删除/固定。只有公开确认事件可成为群共同记忆；游戏隐藏身份在揭晓前不得进入共享记忆。跨角色/跨群召回必须先按可见范围过滤，不能先发给模型再让它保密。

避免 AI 每轮全量读取几万条：近期消息窗口 + 相关事件索引 + 少量长期记忆，按需检索；不压缩覆盖原始聊天记录。存储空间不足必须明确失败并回滚当前变更。

### 4.4 钱包契约

先由统一账本执行带幂等键的预留、扣款、领取和结算，再根据**成功凭据**生成红包卡片与手气王结果。重试同交易号不得二次扣款；失败不得显示已成功。游戏奖励/AI 发红包仅是模拟玩法，不凭模型文本向钱包记账；不同账号的余额与交易需要服务端身份隔离。

## 5. 迭代顺序 / 验收门槛

- **A｜当前首批**：将群聊专属设置归为五类；现有控件迁移而不变更含义；群记忆在原桌面记忆空间出现可用入口，并以群 ID 保存/读取人工确认记忆；补分类与隔离契约。保持 PR #298 Draft。
- **B｜玩法核心**：统一头衔动作、管理员变更记录、多人 @ 与引用；既有接龙/投票增强、玩法插件注册器。
- **C｜秘密游戏**：一局一实例、私聊规则开关、可见性隔离、主持人、身份牌、结算与游戏记忆。
- **D｜群体生活**：自然闲聊与日程、邀请、活动、跨群角色状态和对话记忆；须避免角色持续后台刷屏。
- **E｜钱包与云端联调**：统一红包交易、手气王、跨应用事件、跨账号权限、云端主动通知、Android/iOS 真机完整测试。

每期至少核验：旧群数据和历史不丢；群主/管理员越权拒绝；秘密不被普通群上下文读到；钱包余额/结算不重复；退群后不偷偷加入；手动记忆刷新可见；320/375/390/430px 页面；PWA 更新、离线和存储不足提示；完整 Node、Vite、浏览器、手机实测后才可合并/上线。
