# MAOMAO 双平台移动端验收规范

> 适用于 MAOMAO 的所有新功能、重大修复、主题与页面交互；钱包/账号等涉及持久化数据的功能尤其必须执行。**Android 和 iOS 都是必测平台**。浏览器引擎模拟不等于真实手机验收。

## 覆盖矩阵（每次发布前）

| 平台 | 必测运行环境 | 当前状态 |
| --- | --- | --- |
| Android | Chrome 浏览器及安装到桌面的 PWA | 未验收 |
| Android | QQ 浏览器（用户当前主要使用的浏览器），涉及麦克风/分享等权限时额外核对 | 未验收 |
| iPhone / iOS | Safari 浏览器 | 未验收 |
| iPhone / iOS | Safari「添加到主屏幕」后运行的 Web App / PWA | 未验收 |

如有条件，补充不同屏幕尺寸、横竖屏及其他浏览器。每次记录 **设备型号、系统版本、浏览器版本、运行方式（普通网页/PWA）、测试构建 SHA、结果与复现步骤**。不得把 Android 成功推断为 iOS 成功，也不得把 Playwright Chromium/WebKit 或桌面设备模拟称为「已完成 Android/iPhone 真机测试」。

## 两端必须复核的共同行为

- **账号与隔离**：注册/登录/登出、管理员权限、账号 A/B 切换；不能读取另一账号的聊天、余额、财务流水、订单、亲属卡；超级管理员原有数据不得丢失。
- **钱包与交易**：充值、提现、红包/转账发送及领取、商店/外卖、亲密付及亲属卡；余额与明细一致、重复点击不重复扣款、存储失败时有清晰提示、刷新后可恢复未完成订单、不用默认 1000 覆盖损坏余额。
- **聊天与 AI**：消息发送/保存、独立气泡、图片/语音、回到列表再进入、页面切换后历史不丢失；API 未配置时不得假装成功。
- **PWA / 浏览器差异**：添加到主屏幕、重开/刷新、Service Worker 更新、缓存版本切换、离线时合理提示；Safari 与 Android 浏览器分别验证存储限制与滚动/安全区域。
- **权限与系统集成**：麦克风、分享、图片选择、通知/推送等按各浏览器真实支持情况验证；不支持时必须有可理解的提示，不能把权限失败当作成功。
- **视觉与交互**：顶部状态栏、安全区域、底部 Dock、键盘弹起、输入焦点、细小按钮触区、长按/手势、动画、主题切换和精细交互；尤其检查 iPhone 刘海/底部 Home Indicator 与 Android 系统导航区。

## 钱包双浏览器引擎自动化预检（不是真机验收）

在具备 Playwright Chromium 与 WebKit 浏览器二进制的开发环境中运行：

```bash
npm run test:wallet:mobile-engines
```

该命令运行 `tests/wallet-mobile-engines.browser.mjs`，依次打开 Android 风格的 Chromium 触屏环境和 iPhone 风格的 WebKit 触屏环境，并使用真实的账号隔离脚本及统一钱包模块测试：

- 同一浏览器底层存储中，普通账号 A、普通账号 B 和管理员各自的余额、流水隔离
- 不同账号的未完成购物订单和财务记录隔离
- 同账号两个标签页使用过期余额快照时，不得覆盖新交易
- 输出各引擎是否具有 `navigator.locks` 跨标签页锁能力，用于决定钱包交易的浏览器降级策略
- 任何一个引擎无法启动、缺少安装或测试失败，命令都返回失败；**不能把未运行当作通过**

此命令是桌面浏览器内核的**手机外观与触摸模拟预检**。它并非真实 Android Chrome / QQ 浏览器或真实 iOS Safari，尤其不能证明 PWA 安装、iOS 存储限制、系统权限、推送、原生键盘、真实手势与后台恢复正常。双平台真机验收仍按下方必测矩阵单独完成。

## 验收与发布规则

1. 先运行 Node 契约测试、构建和 Chromium/WebKit 浏览器自动化（如可用），标注为「自动化/模拟」。
2. 再完成上方 **四种必测运行环境** 的真机操作，逐项留存实际结果；没有设备或权限无法验证时注明「未验收」，不能写「通过」。
3. 钱包/账号涉及高风险变更时，需要双平台各自测试账号隔离、正常交易、重复操作、存储异常和中断恢复，验证状态与账目。
4. 遇到平台差异，记录设备、步骤、截图或非敏感日志，在相关 PR 中修复并复测；任何一个必测平台存在关键阻碍时，不标记「双端验收通过」。
5. 未经明确允许，不以测试为名合并 `main`、部署生产环境或制作 APK；不要上传真实 API 密钥、密码、Cookie、个人聊天或支付数据。
