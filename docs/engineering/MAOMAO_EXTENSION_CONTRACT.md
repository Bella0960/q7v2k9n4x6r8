# MAOMAO 模块扩展契约（v1 草案）

> 状态：工程约束与落地清单；不是声称全站插件运行时已经存在。与 #262 / #265 的安全整合一起维护。目标是以后添加功能时走受控接入口，而不是重写整个旧页面。

## 1. 不变约束

- **旧功能不动**：已验收的真人好友聊天、端到端加密、语音气泡、会话列表、001 原始身份及现有正式聊天主题均为回归保护基线。
- **账号只有一个权威来源**：禁止因新增模块创建另一套登录/001 管理员或把不同 Durable Object 命名空间中同名账号视为同一身份。
- **按账号隔离数据**：新增本机数据使用现有 `shared/js/mao-account-scope.js` 或其已验证后继方案；服务器端在每个数据接口验证会话、权限、账号归属。
- **数据库迁移只追加、不重置**：沿用 `worker/lib/migrations.js` 的版本迁移；新增迁移使用下一个独立版本，不修改已部署迁移的含义。
- **可禁用、可回退**：实验功能服务端默认关闭，保留回滚路径，不覆盖正式数据。功能未验收前不调整 `app.mao520.com` 绑定。

## 2. 现有可复用接入口（已存在于整合分支）

| 使用场景 | 现有接口/文件 | 后续扩展方式 |
|---|---|---|
| 聊天首页操作菜单 | `shared/js/chat-action-menu.js` → `window.MAOMAOChatActions.register(descriptor)` | 新动作注册独立 descriptor；不复制/重写菜单 HTML。支持取消注册。 |
| 真人会话列表 | `shared/js/social-chat-list.js` → `window.MAOMAORealChatList.subscribe/refresh/clear/getRows` | 保持数据源与 UI 分离；订阅更新，账号变化时先清空、再验证身份。 |
| 真人好友服务 | `worker/lib/mao-social.js`、`mao-social-e2ee.js` | 在后端会话授权后增量加接口；聊天媒体继续端到端加密，绝不增加明文备用路径。 |
| 服务端持久化 | `worker/lib/migrations.js` 与 `worker/migrations/00xx_*.js` | 独立向前迁移、单独测试；不得因新功能重建已有账号或清库。 |
| 现有页面入口 | 各模块独立 HTML/CSS/JS | 优先追加本模块入口和独立资源；避免一项更新替换整套桌面或主题。 |

> 注意：以上只列当前真实存在的接入口，不表示其他模块已支持统一注册表。

## 3. 新功能必须预留的“缺口”

每个新模块/大型改造应提供下列清单，缺少项目则在 PR 描述中说明：

1. **功能清单**：稳定功能 ID、入口页、依赖、所需权限、服务器开关、可选能力；不要以按钮位置当功能 ID。
2. **UI 插槽**：标明入口属于桌面、聊天首页、聊天工具栏、商城、角色手机或设置；优先注册式接入，缺少注册点时先设计兼容性插槽而非硬编码横向覆盖。
3. **存储接口**：账号归属、schema 版本、读写失败回报、备份与恢复策略。读取损坏数据时禁止静默初始化覆盖原字节。
4. **事件边界**：只在**确认保存成功后**发出 `message:saved`、`friend:approved`、`transaction:posted` 等语义事件；事件结构明确定义、去重且带账号范围。上述事件名是拟定契约，不能当作现有 API 使用。
5. **权限与隐私**：服务端验证角色/账号、拒绝跨账号查询；页面显隐和本机 `001` 文本不能授权管理员权限。不得把 API Key、会话 Cookie、加密私钥传给扩展模块。
6. **接入/退出测试**：模块关闭、无 API、未登录、权限变化、断网、过期会话、双设备、老数据、缓存回退均有明确结果。支持功能开关关闭后仍保留旧数据。
7. **视觉契约**：继承黑白灰、极简编辑式排版和现有主题 token；主题包与气泡样式分开，不能强行全局覆盖。

## 4. 建议的后续基础设施（待实现，不可冒充现成能力）

- 统一的首方模块 manifest 和客户端注册点（桌面应用、聊天操作、商城分类、角色查手机子页）。只加载仓库审查过的首方代码，**不执行用户输入的 JavaScript**。
- 有类型/版本与账号范围的事件分发器；持久化确认后通知下游，避免论坛、朋友圈、足迹与聊天互相直接改存储。
- 模块级开关、资源分包和 PWA 缓存版本管理；新增功能不迫使旧聊天页面一次性加载全部新代码。
- 对外统一的本机数据访问层与备份扩展点，收敛孤立 `localStorage` 余额、消息、图片键。

此基础设施应先在风险低的独立模块落地并跑回归，再逐步迁移论坛、查手机、主题商城、钱包和 AI 主动联系。**不可为了抽象重构而动已验收真人聊天或强行迁移账号数据库。**

## 5. 每次 PR 的交付条件

- 标出触及的主程序/扩展接口、旧数据是否迁移、需要新增哪些可选权限与配置。
- 附不依赖 GitHub Actions 免费额度的本机 Node/构建与浏览器回归结果；涉及手机体验时仍需 Android/iOS 验收。
- 明确“未测试”“仅编译”“隔离预览通过”“真机通过”“已合入 main”“已部署生产”六种不同状态，不可混用。
- 安全分支先隔离测试，确认原始 001 身份/数据与可执行回滚，再考虑正式域名。
